📘 Documentation Complète de SketchFlutter

SketchFlutter est un éditeur visuel d'applications Flutter. Il permet de créer des interfaces graphiquement, de définir une logique simple par blocs, de prévisualiser en direct, puis de compiler un APK via GitHub Actions.

Cette documentation décrit l'architecture du projet, le rôle de chaque dossier/fichier, et fournit un guide pour modifier ou étendre l'application.

Vue d'ensemble

L'application est organisée en couches :

· Modèles (models/) : représentation des données (projet, pages, widgets, variables, etc.) avec sérialisation JSON.
· Services (services/) : opérations sur les données (stockage local, import/export, GitHub, compilation).
· Providers (providers/) : gestion d'état avec Riverpod (projet actif, éditeur, variables...).
· Moteur de rendu (render_engine/) : interprète le JSON du projet en widgets Flutter pour l'aperçu.
· Interface utilisateur (screens/, widgets/) : écrans et composants réutilisables.
· Générateur de code (generator/) : transforme le projet en code Dart Flutter compilable.

Détail du dossier lib/

core/

Contient les constantes globales, utilitaires transversaux et classes d'erreurs.

· constants/
  · app_colors.dart : palette de couleurs de l'éditeur (mode sombre, accents, etc.).
  · app_strings.dart : tous les libellés/textes de l'interface (français).
  · schema_versions.dart : gestion des versions du schéma JSON (migrations).
· errors/
  · project_import_error.dart : exception pour les erreurs d'import .mub.
  · validation_error.dart : exception pour les erreurs de validation du JSON.
· utils/
  · alignment_utils.dart : conversion entre chaînes et Alignment Flutter.
  · color_utils.dart : conversion hexadécimale ↔ Color.
  · debouncer.dart : utilitaire de debounce (recherche, sauvegarde auto).
  · edge_insets_utils.dart : conversion JSON ↔ EdgeInsets.
  · file_utils.dart : lecture/écriture de fichiers, base64, répertoires.
  · json_utils.dart : helpers JSON (lecture typée, copie profonde).
  · text_style_utils.dart : conversion JSON ↔ TextStyle.
  · uuid_generator.dart : génération d'identifiants uniques.

models/

Modèles de données avec fromJson / toJson. Tous sont immuables (champs final, copyWith).

· asset_model.dart : asset (image, police) encodé en base64.
· custom_code.dart : code Dart personnalisé (imports, fonctions, classes).
· dependencies.dart : liste des dépendances externes (pub, git, path).
· design_system.dart : couleurs, styles de texte, espacements globaux.
· generation_settings.dart : paramètres de génération APK (package, version, orientation...).
· logic_block.dart : bloc logique (type, paramètres) et constantes de types.
· navigation_model.dart : page initiale et routes de navigation.
· page_model.dart : page (écran) avec arbre de widgets et liaisons logiques.
· project_metadata.dart : nom, auteur, dates, miniature du projet.
· project_model.dart : racine du projet, agrège tous les sous-modèles.
· variable.dart : variable globale (nom, type, valeur initiale).
· widget_node.dart : nœud de widget (type, propriétés, enfant(s)).

services/

Services métier et communication externe.

· compile_service.dart : orchestration de la compilation (interface CompilationBackend).
· file_download_service.dart : téléchargement de fichiers (APK) avec progression.
· github_service.dart : intégration API GitHub (création repo, upload, workflow).
· project_import_export.dart : import/export du format .mub (JSON compressé gzip).
· project_storage.dart : sauvegarde/chargement local des projets (fichiers JSON + index).

providers/

Gestion d'état avec Riverpod.

· design_system_provider.dart : fournit le design system courant et méthodes de modification.
· editor_provider.dart : état de l'éditeur (sélection, page courante, undo/redo).
· project_provider.dart : liste des projets, projet actif, actions CRUD.
· render_engine_provider.dart : fournit un RenderEngineContext (design system + variables).
· variable_store.dart : magasin des variables globales et leurs valeurs courantes.

render_engine/

Interprète le JSON en widgets Flutter et exécute la logique pour l'aperçu.

· json_widget_parser.dart : parseur principal, fait la récursion et utilise les builders.
· widget_registry.dart : registre des types de widgets supportés.
· render_context.dart : contexte partagé (design system, resolver, parsers, callback setVariable).
· property_parsers/ : convertit les propriétés JSON en objets Flutter.
  · alignment_parser.dart
  · color_parser.dart
  · edge_insets_parser.dart
  · text_style_parser.dart
  · reference_resolver.dart (résout @colors, @text_styles, @spacing, @variables)
· widget_builders/ : construit un widget Flutter pour chaque type.
  · appbar_builder.dart, button_builder.dart, center_builder.dart, etc.
· logic_executor/ : exécute les blocs logiques lors des événements.
  · logic_executor.dart : boucle d'exécution, dispatcher.
  · block_types/ : implémentations des blocs (show_snackbar, navigate, set_variable, condition, loop, math_operation).

screens/

Écrans de l'application.

· design_tab.dart : onglet Design (toile + palette + inspecteur).
· editor_screen.dart : écran principal de l'éditeur avec les onglets.
· export_screen.dart : export / compilation APK.
· home_screen.dart : ancien écran d'accueil (remplacé par project_list_screen).
· logic_tab.dart : onglet Logique (variables + événements).
· pages_tab.dart : onglet Pages (gestion des écrans).
· preview_screen.dart : aperçu en direct (exécution locale).
· project_list_screen.dart : liste des projets (écran d'accueil actuel).
· settings_screen.dart : paramètres de l'éditeur.

widgets/

Composants d'interface réutilisables.

· canvas_area.dart : zone de rendu interactive (zoom, pan, grille).
· color_picker.dart : sélecteur de couleur (champ hex + dialogue RVB).
· dropdown_input.dart : liste déroulante générique.
· icon_picker.dart : sélecteur d'icône Material.
· logic_block_editor.dart : éditeur de blocs logiques (ajout, modification, suppression).
· number_input.dart : champ numérique avec validation et slider optionnel.
· project_card.dart : carte de projet dans la liste.
· property_inspector.dart : panneau d'inspection des propriétés d'un widget.
· variable_manager.dart : gestionnaire de variables (liste + CRUD).
· widget_palette.dart : palette de widgets (barre horizontale).
· widget_tree_view.dart : arborescence des widgets.

generator/

Transforme le ProjectModel en code Dart Flutter compilable.

· code_generator.dart : orchestre la génération (appelle PubspecGenerator et ProjectToDart).
· project_to_dart.dart : génère main.dart, app_state.dart et les pages.
· pubspec_generator.dart : génère pubspec.yaml.
· widget_code_generators/ : générateurs de code pour chaque type de widget.
  · widget_code_utils.dart : helpers partagés (couleurs, EdgeInsets, etc.).
  · container_generator.dart, text_generator.dart, etc.
· logic_code_generators/ : générateurs de code pour les blocs logiques.
  · code_block_generator.dart : dispatcher.
  · set_variable_generator.dart, show_snackbar_generator.dart, etc.

utils/

Ré-export des utilitaires de core/utils pour éviter les imports longs.

· debouncer.dart
· file_utils.dart
· json_utils.dart
· uuid_generator.dart

Comment modifier / ajouter des fonctionnalités

Ajouter un nouveau widget

1. Définir le type dans les modèles (aucun changement nécessaire, WidgetNode accepte tout type).
2. Ajouter le builder dans lib/render_engine/widget_builders/ :
   · Créer un fichier monwidget_builder.dart avec une classe MonWidgetBuilder et une méthode build.
3. Enregistrer le type dans widget_registry.dart.
4. Ajouter le cas dans json_widget_parser.dart.
5. Ajouter le générateur de code dans lib/generator/widget_code_generators/ :
   · Créer monwidget_generator.dart et ajouter le cas dans project_to_dart.dart.
6. Ajouter le widget à la palette dans widget_palette.dart (item).
7. Ajouter les champs d'inspection dans property_inspector.dart (map _widgetPropertyFields).

Ajouter un nouveau bloc logique

1. Définir le type dans logic_block.dart (LogicBlockTypes).
2. Créer l'exécuteur dans render_engine/logic_executor/block_types/.
3. Ajouter le case dans logic_executor.dart.
4. Créer le générateur dans generator/logic_code_generators/.
5. Ajouter le case dans code_block_generator.dart.
6. Ajouter à l'éditeur dans logic_block_editor.dart (dialogue de création).

Modifier le modèle de données

Tous les modèles sont dans lib/models/. Modifiez les champs, les méthodes fromJson/toJson et copyWith. Pensez à mettre à jour la version du schéma dans schema_versions.dart si le format change, et à écrire une migration.

Modifier le générateur de code

Les générateurs sont dans lib/generator/. Pour changer la sortie Dart, modifiez project_to_dart.dart ou les fichiers de widget_code_generators/ et logic_code_generators/.

Modifier l'interface utilisateur

· Écrans : lib/screens/.
· Composants réutilisables : lib/widgets/.
· Thème : app.dart et core/constants/app_colors.dart.

Points d'attention et fichiers obsolètes

Votre arborescence contient des fichiers avec l'extension .bak. Ils sont dus à des sauvegardes automatiques de votre éditeur et ne sont pas utilisés par Flutter. Vous pouvez les supprimer sans risque :

· lib/generator/code_generator.dart.bak
· lib/generator/logic_code_generators/*.bak
· lib/generator/project_to_dart.dart.bak
· lib/render_engine/logic_executor/*.bak
· lib/render_engine/logic_executor/block_types/*.bak
· lib/render_engine/render_context.dart.bak
· lib/screens/preview_screen.dart.bak
· lib/services/compile_service.dart.bak

Nettoyez-les pour une arborescence propre.

---

Éléments manquants / à compléter

· Duplication de projet : le service existe, mais l'action n'est pas câblée dans l'UI.
· Import/export .mub : les services sont prêts, mais les boutons de l'UI affichent un SnackBar "à venir".
· Glisser-déposer dans la toile : l'ajout se fait via la palette, pas par drag.
· Édition visuelle des arbres : widget_tree_view.dart est prêt mais pas intégré dans un panneau latéral.
· Gestion avancée des blocs : if, loop, math_operation existent dans le moteur et le générateur, mais l'éditeur logic_block_editor.dart ne sait encore créer que show_snackbar, navigate, set_variable.
· Réactivité complète de l'aperçu : les variables se mettent à jour via setVariable, mais il faut vérifier que preview_screen reconstruit correctement l'UI après changement.
· Tests : les fichiers de test existent mais sont probablement vides ou minimaux.

---

Tests

Dans test/ :

· parser_test.dart : tester le parseur JSON → Widget (JsonWidgetParser).
· generator_test.dart : tester le générateur de code (CodeGenerator, ProjectToDart).
· import_export_test.dart : tester l'import/export .mub.

Pour les compléter, créez des projets factices (ProjectModel.create, ajout de pages/variables, etc.) et vérifiez que les sorties correspondent aux attentes.

6. Générateur de code (generator/) – conversion du modèle en code Dart compilable.

🛠️ Comment modifier / ajouter des fonctionnalités

Ajouter un nouveau widget

1. Créer le builder dans lib/render_engine/widget_builders/ (ex: monwidget_builder.dart).
2. Enregistrer le type dans widget_registry.dart.
3. Ajouter le cas dans json_widget_parser.dart.
4. Créer le générateur dans lib/generator/widget_code_generators/ (ex: monwidget_generator.dart).
5. Ajouter le cas dans project_to_dart.dart (import + switch).
6. Ajouter l'item dans widget_palette.dart (avec icône).
7. Ajouter les champs dans property_inspector.dart (map _widgetPropertyFields).

Ajouter un nouveau bloc logique

1. Définir le type dans models/logic_block.dart (LogicBlockTypes).
2. Créer l'exécuteur dans render_engine/logic_executor/block_types/.
3. Ajouter le case dans render_engine/logic_executor/logic_executor.dart.
4. Créer le générateur dans generator/logic_code_generators/.
5. Ajouter le case dans generator/logic_code_generators/code_block_generator.dart.
6. Mettre à jour l'éditeur dans widgets/logic_block_editor.dart (dialogue de création).

Modifier le modèle de données

· Tous les modèles sont dans lib/models/.
· Modifiez les champs, fromJson, toJson, copyWith.
· Si le format JSON change, incrémentez schema_versions.dart et ajoutez une migration.

Modifier le générateur de code

· Les générateurs sont dans lib/generator/.
· Pour changer la sortie Dart, modifiez project_to_dart.dart ou les fichiers de widget_code_generators/ et logic_code_generators/.

Modifier l'interface utilisateur

· Écrans : lib/screens/.
· Composants : lib/widgets/.
· Thème : app.dart et core/constants/app_colors.dart.
